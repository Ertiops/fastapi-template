# FastAPI Template

A Python 3.14+ REST API template using **FastAPI, SQLAlchemy async, Dishka, PostgreSQL, and uv**. Users and movies illustrate a layered architecture with typed use cases, storage protocols, and soft deletes.

## Prerequisites

Install Python 3.14, [uv](https://docs.astral.sh/uv/) **0.12.22**, and Docker (for a local PostgreSQL or the containerized application).

No Poetry, poetry.lock, or third-party UUIDv7 generator is required. Dependencies are reproducible from `uv.lock`.

## Local development

```bash
uv sync --locked --python 3.14 --dev
# or: make develop (also installs pre-commit hooks)
```

Create a private `.env` from `.env.example`, replacing the example password and application secret with **new local-only values**. Do not commit any populated `.env` file.

The development Compose file starts **only PostgreSQL**, with a configurable port bound to localhost:

```bash
docker compose --env-file .env -p fastapi-template-dev -f docker-compose.dev.yaml up -d --wait
export APP_DB_DSN='postgresql+asyncpg://app:<YOUR_LOCAL_PASSWORD>@127.0.0.1:25446/app'
uv run --locked python -m app.adapters.database upgrade head
uv run --locked python -m app
```

Default REST development address: http://127.0.0.1:8000. Set `APP_REST_HOST` and `APP_REST_PORT` to configure it.

To stop the dev database without destroying its data: `make local_down` (or `docker compose -p fastapi-template-dev -f docker-compose.dev.yaml down`).

## Docker Compose: application plus PostgreSQL

The main `docker-compose.yaml` builds the application **locally** using a multi-stage Python 3.14 / pinned-uv Dockerfile. PostgreSQL remains on an internal network; the app is exposed only on localhost.

```bash
docker compose --env-file .env -p fastapi-template-app up --build -d --wait
docker compose --env-file .env -p fastapi-template-app exec app python -m app.adapters.database upgrade head
curl -f http://127.0.0.1:18080/docs/openapi.json
curl -f 'http://127.0.0.1:18080/api/v1/users/?limit=2'
docker compose --env-file .env -p fastapi-template-app down
```

If you override `APP_PORT`, use that port in the URLs. The container launches `python -m app` (the actual aiomisc/Uvicorn entrypoint), listening on `0.0.0.0:8080` inside Docker. Docker uses a non-root user and installs production dependencies only.

For test environments use an **independent Compose project name, credentials, and dedicated volumes**, never a production database.

## API routes

| Method | Endpoint | Action |
|---|---|---|
| GET | `/api/v1/users/` | List users with keyset pagination |
| POST | `/api/v1/users/` | Create user |
| GET | `/api/v1/users/{user_id}/` | Get user |
| PATCH | `/api/v1/users/{user_id}/` | Update user |
| DELETE | `/api/v1/users/{user_id}/` | Soft-delete user |
| GET | `/api/v1/movies/` | List movies with keyset pagination |
| POST | `/api/v1/movies/` | Create movie |
| GET | `/api/v1/movies/{movie_id}/` | Get movie |
| PATCH | `/api/v1/movies/{movie_id}/` | Update movie |
| DELETE | `/api/v1/movies/{movie_id}/` | Soft-delete movie |

### UUIDv7 and cursor pagination

New identifiers are generated by the Python 3.14 standard library `uuid.uuid7()` through the common SQLAlchemy `IdentifableMixin`. The PostgreSQL type remains UUID. No historical-ID migration is necessary for this greenfield template.

**Breaking API v1 change:** list endpoints accept `limit` (default 10; 1–100) and optional `after` (a UUID string) instead of `offset`:

```http
GET /api/v1/users/?limit=2
GET /api/v1/users/?limit=2&after=019a2d10-0000-7000-8000-000000000001
```

Response structure is exactly `items` and `next_cursor`:

```json
{
  "items": [],
  "next_cursor": null
}
```

When there is a subsequent page, `next_cursor` is the **last returned record's UUID**; on the last page, including a non-empty one, it is `null`. Send `after=<next_cursor>` to request the following page; stop when it is null.

Both collections are ordered `id DESC`, and database queries use `WHERE id < :after ORDER BY id DESC LIMIT limit+1` while excluding soft-deleted rows. UUIDv7 generally follows generation time but is not a strict global creation-time guarantee across servers.

Any syntactically valid UUID is an acceptable cursor boundary, even when the corresponding row is absent or deleted. Malformed UUIDs, out-of-range limits, `offset`, and unknown query names return **HTTP 422**.

Cursor pagination does **not** guarantee a transaction-wide snapshot across multiple HTTP requests. On a static data set, repeated traversal has no duplicates or skips; concurrent inserts/deletes may affect later pages.

## Testing, linting and migrations

```bash
make test                # full test suite (one worker by default)
make lint-ci             # Ruff + MyPy, non-mutating
make test-ci             # pytest + coverage + JUnit XML
make local-apply-migrations
```

The tests require a **separate** PostgreSQL database and a valid `APP_DB_DSN`, and their fixtures isolate test schemas. GitHub Actions uses Python 3.14 and the same locked uv dependency graph.

Database migrations in `app/adapters/database/migrations` are the baseline table schema. This feature does not rewrite primary keys or require a new Alembic revision.

## Security and environment policy

- `.env.dev` is no longer tracked; `.env.example` has safe placeholders, and Git and Docker ignore populated env files.
- Never reuse example credentials outside local development or publish a populated `.env`.
- Removing a once-tracked env file from a new commit does **not** remove it from old Git history. If any historical secrets were live, rotate them separately.
- No service listens publicly by default via the supplied Docker Compose configurations.
